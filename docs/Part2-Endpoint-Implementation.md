## Authentication approach
The Part 2 requirements specify server-side session management. After successful login, the API stores the authenticated user's `UserId`, `Role`, and `Email` in ASP.NET Core Session. Protected controller actions use `SessionAuthorizeAttribute` to reject unauthenticated requests with HTTP 401 and reject the wrong role with HTTP 403.

Passwords are never stored in their original form. New registrations are hashed with ASP.NET Core Identity's `PasswordHasher<User>`.

## Database approach
Entity Framework Core models map to the seven Part 1 entities:

- Users
- Routes
- Events
- Categories
- Enrolments
- Results
- EventWeather

The application uses SQL Server through `Microsoft.EntityFrameworkCore.SqlServer`. The Part 1 SQL script remains the database creation/seed script and the EF Core model configuration mirrors its table names, keys, relationships, lengths, precision and checks.

## Swagger
Swagger UI is enabled in Development and exposes all controller endpoints. XML documentation is generated by the API project so the endpoint purpose and response information can be displayed in Swagger.
